# Штатный модуль — v1.2-alpha, расширение Editor 1.2.0-alpha.1

## Установка и обновление

Codex при FIRST_RUN автоматически запускает Python 3.9+:

```sh
python "AI Assistant/Installer/assistant_tools.py" --project "/полный/путь/проекта" install
python "AI Assistant/Installer/assistant_tools.py" --project "/полный/путь/проекта" inventory
```

В Windows допустим `py -3`. Отсутствие Python — блокер установки, а не разрешение
скачивать неизвестные программы. Альтернатива: агент через Unity-мост копирует
проверенные файлы `Installer/package~` в `Packages/com.vrc-avatar-assistant.editor`,
сохраняя существующие данные; не переписывает manifest/lock вручную. Предпочтителен
установщик: он проверяет собственность и локальные правки. Это embedded Editor-пакет,
не требуется внешний сервер или облако. Исходный `package~` — поставка; активен
только пакет в Packages. Он не включается в Player благодаря Editor-only asmdef.

Дождаться завершения импорта/компиляции. Через мост прочитать
`VrcAvatarAssistant.AssistantHistory.Version`, вызвать `SaveProfile()`, затем
`Record("health-check", "editor", "installed", "ai")`, `Flush()`, `Recent(5)`.
Проверить чтение события из `AI Assistant/History/events.jsonl`. До этой проверки
статус установки NOT_TESTED. Не устанавливать заново при каждом задании.

Unity 2022.3 — целевой API, не гарантия совместимости со всеми версиями SDK/Unity.

Обновление инструкции из отдельно распакованного комплекта:

```sh
python "AI Assistant/Installer/assistant_tools.py" --project "/проект" update --source "/обновление/AI Assistant"
python "AI Assistant/Installer/assistant_tools.py" --project "/проект" install
```

Обновляются только правила, алгоритмы, шаблоны и поставка модуля. History,
накопленные Solutions/KNOWLEDGE_BASE, предпочтения и журналы AvatarAgent, Reports
сохраняются. Старые версии заменяемых файлов копируются в Backups. Обновление
пакета блокируется при локальных изменениях его кода. Автоматического скачивания
обновлений нет: агент сравнивает версии по поручению и использует выбранную поставку.

## История и авторство

`Tools > VRC Avatar Assistant > Open`: текущая задача, статус записи, последние
события, заметки пользователя, пауза, STOP, лимиты и проверка выбранного аватара.
Модуль стартует вместе с редактором после установки. Журнал JSONL локальный.
Изменения свойств группируются по автору, объекту и пути свойства в пределах двух
секунд; значения свойств не записываются. Ротация: 16 MB на файл, 4 архива по умолчанию.
Изменения пакетов проверяются раз в 10 секунд. Нет наблюдения при закрытом Unity.

`user` — явная заметка пользователя; `ai` — синхронный RunAgentStep или явная
служебная запись Codex; `unknown` — изменения без подтверждённого источника.
События Unity не содержат надёжного авторства: ручные действия и сторонние плагины
без маркировки относятся к unknown. Отложенные события после AI-команды также могут
быть unknown. Поэтому журнал не обещает точного автора каждой правки.
Наблюдаются Undo-события, импорт/перенос/удаление assets, сохранение сцен и manifest.
Действия без Undo могут не дать подробного события; они обнаруживаются частично
проверкой состояния. Разница до установки и во время паузы не реконструируется.

## Протокол агента и совместные изменения

1. Прочитать `Recent(30)`, профиль и фактический объект. Согласованное ранее
   требование устанавливать и использовать наблюдатель разрешает его локальную работу.
2. `BeginTask(id, exactAvatar, constraints)`; зафиксировать внешние общие материалы,
   контроллеры и прочие объекты через `WatchDependencies(...)` до первой правки.
3. Перед каждым шагом сверить файлы зависимостей с контрольной точкой; изменять
   объект внутри `RunAgentStep(() => { ... }, affectedObjects)` в одном синхронном
   вызове главного потока. Register Undo обязателен для изменений, где API его поддерживает.
4. Модуль сравнивает сериализованное состояние аватара и переданных зависимостей.
   При несовпадении/STOP/компиляции/Play Mode запрещает следующий защищённый вызов.
   После конфликта EndTask, перечитать состояние и создать новую задачу; не сбрасывать
   конфликт ради продолжения по старому плану.
5. Проверить результат и EndTask(result). После domain reload задача INTERRUPTED,
   автоматическое возобновление записи аватара запрещено.

Это совместный протокол, а не блокировка всего Unity: прямой C# вне RunAgentStep
может обойти его. Асинхронные операции и новые зависимости требуют отдельной
проверки. STOP не отменяет уже запущенный код. Snapshot больших аватаров может быть
дорогим — профилировать на реальном проекте. Окно показывает только 20 последних событий.

## Контрольные точки

Перед правкой агент проверяет несохранённые изменения пользователя: сохранять
их без команды нельзя. Контрольная точка фиксирует только сохранённые байты
точно перечисленных файлов; для Assets автоматически добавляются `.meta`.
Указать также путь каждого нового создаваемого файла до создания.

```sh
python "AI Assistant/Installer/assistant_tools.py" --project "/проект" checkpoint "Assets/Avatar.prefab" "Assets/NewMenu.asset"
# после изменения и сохранения только порученных файлов:
python "AI Assistant/Installer/assistant_tools.py" --project "/проект" seal CHECKPOINT_ID
# предварительный просмотр восстановления:
python "AI Assistant/Installer/assistant_tools.py" --project "/проект" restore CHECKPOINT_ID
# при порученном восстановлении и закрытом Unity:
python "AI Assistant/Installer/assistant_tools.py" --project "/проект" restore CHECKPOINT_ID --apply
```

Восстанавливать на закрытом редакторе, после проверки новых ручных изменений.
После seal нельзя переписать эталон повторным seal. Новое изменение любого файла
блокирует восстановление всей точки. Проверяется целостность backup, создаётся
rescue-точка текущего состояния. Многофайловая запись не является транзакцией:
при ошибке чтения/записи использовать rescue и отчёт, не обещать универсальный откат.
Контрольные точки не удаляются автоматически; явно выбранные ненужные точки можно
очищать после проверки сохранённой альтернативы. Общий backup-бюджет задаёт пользователь.

## Проверки и зависимости

`Check(exactAvatar, operation, expectedChild, expectedComponent)` поддерживает
general/clothing/prop/menu/materials; ищет отсутствующие scripts/references/materials
и ожидаемые объект/компонент. Результат FAILED либо PARTIAL, не VERIFIED целиком.
Rig/клиппинг, expression-меню, параметры/бюджет, анимации, shader-платформа,
SDK build и VRChat клиент — отдельные проверки по чек-листу ниже. Отчёты в Reports.
Создать точные критерии в TASK_SCOPE до выполнения, записать доказательства после.

inventory читает фактические manifest/lock и embedded packages, сохраняет
package-inventory.json. Связи зависимостей берутся из lock; purpose, required_by,
avatar_usage, removal_risk дополняет агент по фактическим ссылкам и документации.
Наличие пакета не доказывает его использование; UNCLASSIFIED/NOT_TESTED допустимы.
Пользовательские аннотации сохраняются при повторном сканировании.

## Приёмка в Unity — выполнить до заявления о готовности

- Чистый тестовый проект: FIRST_RUN, компиляция, health-check и повторная установка.
- Ручная правка Transform/материала, создание/удаление объекта, prefab save,
  импорт/перемещение asset: проверить события и честное авторство unknown.
- RunAgentStep: запись ai; между двумя шагами вручную изменить аватар или заранее
  зарегистрированный материал: следующий шаг должен отказать и сохранить ручную правку.
- STOP, пауза, возобновление, domain reload, перезапуск редактора, ротация журнала.
- Check каждого типа на исправном и заведомо сломанном тестовом аватаре.
- Контрольная точка prefab+.meta: preview, restore на закрытом Unity, повторное
  открытие и SDK validation; конфликт более поздней ручной правки должен блокировать restore.
- Обновление: журналы/память/предпочтения сохранены, изменённый код пакета не перезаписан.
- Player/аватарная сборка: Editor-сборка отсутствует; отдельно проверить SDK.

Удаление AI Assistant не удаляет установленный Editor-пакет. Сначала отключить/
удалить пакет из Packages по поручению, затем удалять служебные данные: иначе
наблюдатель продолжит создавать History. Не переносить History в новый проект.
